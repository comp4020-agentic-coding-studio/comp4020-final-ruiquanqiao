# Crit 8 reflection

## What was the breakthrough that moved the work forward?

Realising that I had become the project's error detector. The agent's first
plan for the remake left out the police and the weapons, and I caught it
because I remembered the game. I could have kept doing that, one missing
detail at a time, but I would have been checking every answer against a
memory that is itself patchy. The breakthrough was turning the original into a
ledger: every mechanic with a source, a decision and, once built, a test that
proves it, with a spec check that refuses a row without them. After that the
question stopped being "did the agent forget something" and became "is there a
row for this", which anyone can answer. The same move then caught two more
gaps I had not seen coming, the look of the game and what happens when bikes
touch, because each one turned out to be a whole category the research had
never asked about.

## What did this work change about who I want to be as a software developer?

It made me less trusting of fluent output, including my own memory. The first
versions of this game looked plausible and were wrong in ways I only noticed
by riding them or by putting a frame beside the original. I want to be the
developer who sets up the thing that would catch the mistake before arguing
about the mistake: a scripted ride that prints numbers, a screenshot beside
the source, a test that fails on purpose before I trust it to pass. I also
want to be honest in the record about what I chose against the source, like
leaving out the lean key I never used, instead of letting differences hide.
